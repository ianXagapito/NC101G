I. Project Overview

The NC 101 Networks and Communications Project is a culminating, outcome-based group project designed to allow 4th-year BS Computer Science students to apply their knowledge of computer networking in a practical and systematic computing environment.

The project requires students to identify a real-world networking problem or need and develop a working network-based solution. The project should demonstrate both a logical approach to network design and a systematic approach to configuration, implementation, testing, troubleshooting, security, and documentation.

The project must demonstrate how computer systems, system software, and application software communicate and operate through a network — either through a Local Area Network (LAN), an online/WAN environment, or a combination of both.

The project should integrate appropriate networking concepts such as:

OSI & TCP/IP modelsIP addressing & subnettingStatic/dynamic IP Default gatewayDNSDHCPNATNetwork topology Network devicesNetwork protocolsClient-server architecture File/resource sharingNetwork securityNetwork troubleshooting Network-aware applicationsTCP/UDP communicationSocket programming Local & online connectivityPerformance & reliability

The project is intended to demonstrate that students can move from problem identification → network planning → configuration → application/system integration → testing → troubleshooting → documentation → professional presentation.

II. Project Purpose

The project aims to provide students with an opportunity to:

  1. Apply networking theories and principles to a real-world computing problem.
  2. Design an appropriate network architecture based on identified requirements.
  3. Configure physical, logical, and software-based networking components.
  4. Demonstrate communication between networked computers and systems.
  5. Deploy or integrate an application/system that operates through the network.
  6. Apply appropriate network protocols and addressing schemes.
  7. Configure basic network services such as DHCP, DNS, file sharing, or web services when applicable.
  8. Demonstrate secure and responsible use of network resources.
  9. Test network connectivity, performance, reliability, and functionality.
  10. Troubleshoot network and application communication problems.
  11. Document network configurations and system procedures.
  12. Communicate and defend technical decisions professionally.

IV. Project Concept

The project should follow the following basic structure:

  1. Real-World Problem
  2. Network Requirements
  3. Network Design
  4. Network Configuration
  5. System/Application Integration
  6. Local/Online Communication
  7. Testing and Troubleshooting
  8. Security Validation
  9. Documentation
  10. Final Demonstration and Defense
The project should not be limited to simply drawing a network diagram or connecting computers. A successful project must demonstrate a working network environment and show how an application, service, or computing system operates through that network.

VI. Required Networking Component

Every project must have a clearly identifiable networking component. The project should demonstrate at least several of the following:

Network InfrastructureLAN/WLAN, router, switch, access point, NIC, Ethernet/RJ45 cabling, Internet/WAN connection, virtual network environment
Network ConfigurationIP addressing, subnet mask, default gateway, DNS, DHCP, NAT, static IP, dynamic IP, VLAN when appropriate
Network ServicesWeb service, file sharing, database access, DNS service, DHCP service, authentication service, remote access, cloud/online service
Application CommunicationClient-server communication, TCP, UDP, HTTP/HTTPS, FTP/SFTP where appropriate, socket programming, REST/API communication, database-server communication
SecurityUser authentication, password protection, access control, firewall rules, network segmentation, secure protocols, basic data protection

VII. Local and Online Requirement

Whenever technically and financially feasible, the project should demonstrate both:

A. Local Network Operation

ExampleClient Computer → Switch → Server → Application/Database

Students should demonstrate that computers connected to the LAN can access the required system or service.

B. Online/WAN Operation

ExampleClient → Internet → Web/Application Server → Database

Students should demonstrate how the system can communicate outside the local network when the proposed project requires online access.

Important: A project does not need to expose an actual server directly to the public Internet merely to satisfy this requirement.

Students may use:

Virtual machinesPacket Tracer / GNS3 / EVE-NGLocalhost/LAN server Cloud hostingCloud databaseWeb hostingVPN Virtual private networksSimulated WAN environmentsOther instructor-approved environments

The method must be clearly documented.

IX. Examples of Acceptable Projects

The following are examples only. Groups may propose other projects subject to approval.

1. School Laboratory Network and Resource Sharing System

A LAN connecting student computers to a server providing file sharing, web services, user access, and shared resources.

2. Network-Based Inventory Management System

A client-server inventory application where multiple computers access a centralized database through a LAN.

3. Small Business Point-of-Sale Network

A network connecting POS terminals, database/server, printer, and administrator workstation.

4. Computer Laboratory Management System

A network-based system for monitoring computers, users, equipment, and laboratory resources.

5. Network-Based File Management System

A controlled file-sharing environment with authentication and user permissions.

6. Client-Server Chat or Communication System

A TCP/UDP or socket-based application demonstrating communication between multiple network clients.

7. Online Student Service System

A web-based application accessible through a local network and/or online environment.

8. Network Monitoring and Administration System

A system that monitors network connectivity, devices, availability, or selected network performance indicators.

9. Small Office Network Infrastructure

A complete simulated or physical office network containing workstations, server, router, switch, DHCP/DNS, Internet access, and security controls.

10. Hybrid Local and Online System

A system where users access services locally while selected services are available online.

X. Projects That Should Not Be Approved

Projects should be revised or rejected when they:

  • Are purely software applications with no meaningful networking component.
  • Only create a static website.
  • Only create a database without network implementation.
  • Only create a network diagram without configuration.
  • Only configure Packet Tracer without demonstrating the purpose of the network.
  • Have no identifiable real-world problem.
  • Cannot demonstrate network communication.
  • Depend entirely on copying an existing project.
  • Cannot reasonably be completed within the project period.
  • Require resources or technologies that are unavailable to the group.
  • Violate institutional policies, privacy requirements, or applicable laws.
Part I — Proposal Defense

XI. Purpose of the Proposal Defense

The Proposal Defense determines whether the proposed project is:

  • Relevant
  • Technically feasible
  • Network-oriented
  • Outcome-aligned
  • Achievable within the given period
  • Appropriate for 4th-year BSCS students

The proposal defense is also intended to prevent groups from developing projects that are too simple, too broad, or unrelated to the course outcomes.

XII. Proposal Defense Panel

The Proposal Defense shall be conducted before an assigned panel. The panel may consist of:

  1. Project Instructor/Adviser
  2. Networking/Technical Panelist
  3. Software/Systems Panelist
  4. Other designated faculty member/s

XIII. Proposal Defense Fee

Panel Fee
₱1,000.00 per group

A panel fee shall be collected for the conduct of the project defense, subject to the applicable institutional policies and approval.

The fee is intended to support expenses associated with the formal defense process, including panel participation, evaluation, documentation, and administrative requirements.

XIV. Simplified Proposal Format

The proposal should be concise and focused. A recommended proposal length is approximately 5–10 pages, excluding appendices.

1. Title Page

Include: school, college/department, course, project title, group number, members, instructor/adviser, date.

2. Proposed Project Title

The title should clearly indicate: System + Purpose + Target Users + Networking Context

ExampleNetwork-Based Inventory and Monitoring System for a Small Retail Store

3. Background of the Project

Briefly explain: what problem exists, who experiences the problem, why the problem is important, how networking contributes to the solution.

Recommended length: 1–2 pages

4. Problem Statement

Identify the major problem and specific problems.

Example — General Problem The organization currently experiences difficulty in sharing inventory information between multiple workstations.
Specific Problems
  1. Inventory records are stored separately.
  2. Users cannot access updated information simultaneously.
  3. Manual data transfer causes delays.
  4. There is no centralized access control.
  5. Network availability is not monitored.

5. Project Objectives

Objectives should be measurable.

Example At the end of the project, the group shall be able to:
  1. Design a network topology appropriate for the target environment.
  2. Configure IP addressing and network connectivity.
  3. Configure a centralized server or network service.
  4. Develop or deploy an application accessible by network clients.
  5. Implement basic network security controls.
  6. Test connectivity and system functionality.
  7. Document the complete network and system configuration.

6. Proposed Solution

Briefly explain: what will be developed, how it will work, who will use it, how computers will communicate, and what network services are required.

7. Proposed Network Architecture

Provide a simple diagram showing:

ExampleClients → Switch/Router → Server → Application/Database/Internet

The diagram should identify: devices, IP addresses or network ranges, servers, clients, network connections, Internet connection, and network services.

Part II — Final Defense

XIII. Purpose of the Final Defense

The Final Defense evaluates whether the group successfully transformed the approved proposal into a working network-based computing solution. The final defense must demonstrate actual evidence of:

Network connectivityNetwork configurationApplication/system operation Local communicationOnline communication (if in scope)Network services SecurityTestingTroubleshootingDocumentation Individual & group understanding

XIX. Final Project Requirements

The completed project must demonstrate the following major components.

A. Network Component

The group must present: network topology, IP addressing scheme, subnet configuration, network devices, network services, routing (where applicable), VLAN (where applicable), DNS/DHCP (where applicable), Internet/WAN connection (where applicable).

B. System/Application Component

The project must contain a functional application, client-server system, web-based system, network service, network management system, communication system, or other approved computing solution. The system must communicate through the implemented network.

C. System Software Component

Where applicable, demonstrate how the system operates using appropriate operating system, server software, web server, database server, network service, virtual machine, network configuration utility, firewall, and authentication mechanism.

The goal is to show that system software and application software can operate together through the network.

XX. Required Final Demonstration

During the Final Defense, the group should demonstrate the project in the following sequence:

1Network Startup

Show network devices, server, clients, and physical/virtual connections.

2Network Configuration

Show IP addresses, subnet mask, gateway, DNS, DHCP, and routing (if applicable).

3Connectivity Test

Demonstrate ping, client-to-server communication, server-to-client communication, DNS resolution (if applicable), and Internet connectivity (if applicable).

4Application Demonstration

Show the actual application/system operating through the network.

5Multi-Client Demonstration

When applicable, demonstrate two or more clients accessing or communicating with the system simultaneously.

6Network Service Demonstration

Demonstrate applicable services such as DHCP, DNS, file sharing, web server, database server, remote service, API, or socket communication.

7Security Demonstration

Demonstrate user authentication, access permissions, firewall/access control, secure communication, network segmentation, and other approved security mechanisms.

8Troubleshooting Demonstration

The panel may provide or request a simple network problem. Students should explain how they would:

  1. Identify the problem.
  2. Determine the affected layer/component.
  3. Test the connection.
  4. Identify the cause.
  5. Apply corrective action.
  6. Verify the solution.

XXI. Simplified Final Manuscript Format

Chapter 1 — Project Overview

1.1 Background  ·  1.2 Problem Statement  ·  1.3 Objectives  ·  1.4 Scope and Limitations  ·  1.5 Significance of the Project

Chapter 2 — Technical Foundation

Discuss only the concepts directly related to the project: networking concepts, OSI/TCP-IP, protocols, network topology, IP addressing, client-server architecture, network services, security, and related technologies.

Chapter 3 — Network and System Design

Include network architecture, physical topology, logical topology, IP addressing table, device configuration, server configuration, application architecture, database architecture (if applicable), data flow, and communication protocols.

Chapter 4 — Implementation

Include hardware setup, network configuration, server configuration, software installation, application deployment, network integration, and security configuration.

Chapter 5 — Testing and Evaluation

Include connectivity testing, application testing, network service testing, multi-client testing, security testing, performance testing, and troubleshooting results.

Chapter 6 — Conclusion and Recommendations

Include project accomplishment, problems encountered, solutions applied, lessons learned, recommendations, and possible future improvements.

  • Testing

A member should not receive full credit for work that he/she cannot explain or demonstrate.
